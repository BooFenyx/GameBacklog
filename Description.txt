AuthController

logger (ligne 16) — instance de Logger NestJS. Sert uniquement à journaliser les erreurs côté serveur, ici dans le catch de steamReturn

(ligne 72) : quand la vérification OpenID ou l'appel Steam échoue, on trace l'erreur dans la console du serveur avant de rediriger le front vers ?auth=error (le front, lui, ne voit jamais le détail).

steamLogin (ligne 28) — le point d'entrée GET /api/auth/steam, appelé par login() du front (window.location.assign('/api/auth/steam')). Il ne fait qu'une chose : construire l'URL OpenID vers Steam et res.redirect() dessus. C'est la porte d'entrée du flux d'authentification.

Pourquoi @Req() req: Request — parce que l'URL de redirection doit être calculée à partir de la requête réelle :
- req.protocol + req.get('host') donnent l'origine effective (http://localhost:3000, ou https://... derrière le proxy Render — d'où le trust proxy dans app.setup.ts),
- req.query contient les paramètres openid.* renvoyés par Steam,
- req.session permet d'écrire/destroy la session.
@Req() injecte l'objet Express brut ; sans lui, Nest ne donne accès à rien de tout ça.


realm (ligne 29) — l'identité de l'application aux yeux de Steam : http://localhost:3000. OpenID l'utilise pour valider que le retour se fait bien vers la bonne origine (anti-contrefaçon).

returnTo (ligne 30) — l'URL où Steam renvoie le navigateur après connexion : /api/auth/steam/return, i.e. steamReturn.

steamReturn (ligne 39) — le callback. Il : vérifie la réponse auprès de Steam (verifySteamCallback), récupère le profil, régénère l'identifiant de session (protection contre la fixation de session, lignes 54-60), écrit steamId/user dans la session, puis redirige vers FRONTEND_URL/?auth=success (ou ?auth=error).

@Get('me') + @Header('Cache-Control', 'no-store') (lignes 84-85) — GET /api/auth/me est l'endpoint que AuthProvider interroge au montage pour restaurer la session. Le @Header ajoute l'en-tête Cache-Control: no-store à la réponse : sans lui, un navigateur ou un proxy pourrait mettre en cache « connecté/déconnecté » et servir un état obsolète — par exemple afficher connecté après un logout.

interface GetPlayerSummariesResponse (lignes 17-26)
purement typage TypeScript. Steam répond en JSON libre ; 
cette interface décrit la forme exacte de la réponse de ISteamUser/GetPlayerSummaries (response.players[] avec steamid, personaname, etc.).
Elle sert au as de la ligne 120 : sans elle, data.response?.players ne compilerait pas.
Elle n'existe qu'à la compilation, zéro effet à l'exécution.

declare module 'express-session' (lignes 28-33) augmentation de module. 
Le paquet express-session ne déclare pas de champs custom sur req.session ;
ce bloc lui ajoute steamId?: string et user?: SteamProfile | null.
C'est ce qui permet au contrôleur d'écrire req.session.user = profile (auth.controller.ts:63) et de lire req.session.user (ligne 87) sans erreur de type.
Sans ça, TS dirait « la propriété 'user' n'existe pas sur SessionData ».

@Injectable() (ligne 35) — décorateur NestJS qui dit : « cette classe peut recevoir des dépendances injectées par son constructeur ».
Ici il reçoit ConfigService (ligne 39) pour lire STEAM_API_KEY.
C'est lui qui permet à AuthModule de l'instancier et au contrôleur de l'obtenir via injection.

buildSteamLoginUrl(returnTo, realm) (lignes 46-57) — construit l'URL complète vers laquelle rediriger le navigateur.
Elle met dans la query les 6 paramètres OpenID obligatoires :

- openid.ns : le namespace du protocole OpenID 2.0,
- openid.mode = checkid_setup : « je veux identifier cet utilisateur »,
- openid.return_to : où Steam revient après (/api/auth/steam/return),
- openid.realm : l'origine autorisée (le realm du contrôleur),
- openid.identity + openid.claimed_id = identifier_select : demande un identifiant générique 
comme on ne sait pas encore qui se connecte, on demande à Steam de renvoyer l'identité de son choix.
Aucune clé API ici : OpenID ne en demande pas.

openid.claimed_id 
l'identité réclamée par l'utilisateur, renvoyée par Steam au retour.
C'est dans cette URL que se cache le SteamID, sous la forme https://steamcommunity.com/openid/id/76561198.... La regex de la ligne 95 (/\/id\/(\d{17,25})$/) l'en extrait.
La différence avec openid.identity : claimed_id peut contenir des infos de confirmation, c'est lui qu'on filtre réellement.

URLSearchParams() — classe standard du navigateur/Node qui sérialise un objet en query string encodée (a=1&b=2, avec échappement des caractères spéciaux). Utilisé deux fois :
- ligne 47 : pour construire la requête vers Steam (params openid.*),
- ligne 75 : pour rebâtir le corps du POST de vérification — on repasse tous les params openid.* reçus
on force openid.mode = check_authentication, et Steam répond is_valid: true/false.
C'est la re-vérification serveur à serveur : sans elle, on ferait confiance à une URL que n'importe qui pourrait forger.

claimedId (ligne 65-68) — variable locale : le paramètre openid.claimed_id de la query de retour, seulement s'il est une string.
null sinon → la fonction renvoie null et le contrôleur redirige en ?auth=error.
C'est la garde d'entrée avant le POST de vérification : pas d'identité, pas de suite.
